Q2: Describe what your script does, step by step, from opening a Parquet file to writing an output
line
//The pipeline works as follows. A worker process opens a Parquet file with PyArrow and reads rows one at a time, selecting the mp4 column. It identifies each video by the Parquet filename and zero-based row index. The MP4 bytes are passed to PyAV through an in-memory buffer. PyAV decodes every frame, extracts presentation timestamps, and converts frames to BGR. Frames are grouped into seconds using timestamps relative to the first decoded frame. YOLO11l processes batches of frames with the required resolution, confidence, and IoU settings. Predictions are aggregated using the 50% object-presence rule and median people count. JSON records are written incrementally, and failed videos produce an error record. The current architecture uses two separate GPU worker processes, each processing its assigned Parquet files; I did not implement an asynchronous producer-consumer decoding thread.

Q5:Describe one suggestion from an AI tool that was wrong or that you decided not to use.
How did you find out it was wrong, or why did you reject it?
A clear example was Antigravity introducing adaptive uniform frame sampling at 6 FPS and describing it as a performance optimization. That was wrong because the assignment explicitly requires every decoded frame to be processed. Sampling only six frames per second changes the frame population used for the majority calculation and can change the resulting object and people predictions. I caught this by comparing the generated code and README against the original specification, and I instructed Antigravity to remove temporal sampling and use each video’s timestamps instead of a fixed frame rate. Other problematic AI-generated changes included a TensorRT export without verifying the evaluation environment, assuming FP16 would produce identical predictions without testing, and suggested accuracy/runtime figures in its write-up notes that were never measured. The 6 FPS sampling example is the clearest one to discuss.

With one more week, I would focus on optimization and completion. The full 50-file run takes so much time that I did not get to review the code for refactoring and optimization. Concretely, I would: profile inference, preprocessing, and decoding separately; benchmark different batch sizes systematically; improve multi-GPU workload balancing; add checkpoint/resume capability so interruptions do not lose completed results; test unusual codecs, variable frame rates, and rotated videos; validate optimized outputs against reference results; and complete the full dataset processing.
